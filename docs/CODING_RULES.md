# コーディング規約 (GAS & AI コンテキスト用)

このプロジェクトにおけるGASの実装ルールです。GitHub CopilotやCursorなどのAIエディタも、このルールを前提にコードを生成してください。

## 1. 基本方針
- **モダンJavaScriptの活用**: `var` は使用せず、`const` と `let` のみを使用すること。
- **関数定義**: アロー関数 (`() => {}`) を積極的に使用すること。
- **分割代入**: スプレッド構文や分割代入を適宜活用して可読性を上げること。

## 2. GAS特有のルール・最適化
- **スプレッドシートの操作（重要）**:
  - ループ処理の中で `getValue()` や `setValue()` を絶対に実行しないこと（処理速度が著しく低下するため）。
  - 必ず `getValues()` を使って二次元配列としてデータを一括で取得し、メモリ上で計算・加工を行ってから、最後に `setValues()` で一括書き込みをすること。
- **実行時間制限の考慮**:
  - GASには「1回の実行は6分まで」という制限があります。大量のデータを扱う場合はタイムアウトに注意した設計にすること。

## 3. 命名規則
- 変数・関数名はキャメルケース (`camelCase`) を使用すること。
- 外部から直接呼ばれない内部用の関数（プライベート関数）は、GASエディタのマクロ一覧に表示させないため、名前の末尾にアンダースコアをつけること（例：`processData_()`）。

## 4. エラーハンドリング
- APIの受け口となる関数では、必ず `try-catch` ブロックを使用し、エラーが発生した場合は `API_SPEC.md` に定義されたエラーレスポンスの形式（JSON）で返却すること。
