# 卸システム（Wholesaler System）要件・設計定義書

## 1. システムの役割
本システムは、卸業者が請求データ（CSV）をアップロードし、その後の審査・支払いステータスを確認するためのフロントエンド・インターフェースです。
「データの一貫性」を保つため、**本システム自体にデータベース（スプレッドシート等）は保持せず**、すべてのデータ操作はBack Office側のAPIを経由して行います。

## 2. 主要機能（画面UI）
### 2.1 CSVアップロード & プレビュー画面
- **機能**: ユーザーが手元の請求CSVを選択し、登録前に内容を確認する画面。
- **処理フロー**: 
    1. CSVを読み込み、JavaScriptで内容をパース。
    2. 画面上のテーブルにプレビュー表示。
    3. 簡易バリデーション（必須項目の漏れ、数値形式の不備など）を実行し、エラーがあればその場で警告。
    4. 「確定」ボタン押下により、Back Officeの「新規登録API」を呼び出し。

### 2.2 請求書ステータス一覧画面
- **機能**: 過去に提出した請求書の現在の状況をリアルタイムで確認する画面。
- **処理フロー**: 
    1. Back Officeの「一覧取得API」を呼び出し（自社の卸IDでフィルタリング）。
    2. 最新のステータス（承認待ち、差戻し、支払い完了など）を表示。

### 2.3 再提出（修正アップロード）機能
- **機能**: ステータスが「卸差戻」または「否認差し戻し」のデータに対し、修正版を提出する画面。
- **仕様**: 
    - 対象レコードの横に「再提出」ボタンを配置。
    - 再提出時に、**元の請求書ID（Parent_ID）**を保持した状態で新しいCSVをアップロード。
    - Back Officeの「再提出登録API」を呼び出し、新旧データの紐付けを維持。

## 3. 内部ロジック（API連携）
- **通信方式**: `google.script.run` または `UrlFetchApp` を使用。
- **データ保持**: データの原本はBack Office側にのみ存在し、卸側は「表示」と「送信」のみを担当。

## 4. ステータス定義（共通）
以下のステータスを表示に利用する：
- `unprocessed`: 未検閲
- `returned_to_wholesaler`: 卸差戻
- `ready_to_import`: 取込待ち
- `pending_approval`: 確認待ち（加盟店確認中）
- `all_approved`: 承認完了
- `dispute_returned`: 否認差し戻し（加盟店否認）
- `rejected`: 取込NG（論理削除）
- `paid`: 支払い完了
