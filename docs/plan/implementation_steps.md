# 卸システム（Wholesaler System）実装ロードマップ・プロンプトガイド

本ドキュメントは、卸システムのPoC開発（GAS + HTML Service）を、GitHub Copilotを用いたバイブコーディングで最速で進めるためのスプリント計画と指示書のベースです。

## 🚀 実装ステップ

### 【Sprint 1】コア機能：新規CSVのパース・プレビュー・送信
まずは「データを作る・送る」という一番重い部分を終わらせます。ここはFE（フロントエンド）中心の実装になります。

- [ ] **Step 1: UIのガワ作成 (FE)**
  - HTML/CSSで「ドラッグ＆ドロップ対応のCSVアップロードエリア」を作成。（`DESIGN.md` のスタイルガイドを適用）
- [ ] **Step 2: CSVパース処理の実装 (FE)**
  - `FileReader` APIを使って、アップロードされたCSVをブラウザ上でJSON配列に変換する共通関数を作成。
- [ ] **Step 3: バリデーション＆プレビュー描画 (FE)**
  - パースした配列をテーブル形式で画面にレンダリング。
  - ヘッダーなしCSVであることを前提に、「1列目は加盟店コード、2列目は金額…」とマッピング。
  - 「必須項目抜け」「金額が数値以外」などのエラーがあれば、行を赤くハイライトする処理を追加。
- [ ] **Step 4: 送信処理とBE（GAS）のモック作成 (FE/BE)**
  - 「確定」ボタンで `google.script.run.sendInvoiceData(jsonData)` を発火。
  - **[BE側]** GASの `コード.gs` に受け皿となる関数を作り、一旦は卸側の見えないスプレッドシート（またはログ）にモックとして保存する処理を実装。（※BackOfficeのAPIができるまでの仮処理）

### 【Sprint 2】データの確認：ステータス一覧と詳細画面
Sprint 1でモック保存したデータを読み込み、画面に表示します。

- [ ] **Step 5: データ取得APIのモック作成 (BE)**
  - **[BE側]** GASでモック用シートからデータを読み取り、JSONで返す `getInvoices()` と `getInvoiceDetail(id)` を作成。
- [ ] **Step 6: ステータス一覧画面の実装 (FE)**
  - 取得したデータをテーブル表示。
  - `pending_approval` や `returned_to_wholesaler` などのステータス値を、色付きのタグ（バッジ）に変換して表示するコンポーネントを作成。
- [ ] **Step 7: 詳細画面の実装 (FE)**
  - 一覧の行クリックで詳細画面を表示（パラメータでIDを渡すか、SPA的にDOMを書き換える）。
  - ヘッダー情報（合計金額、ステータス）と、明細行のテーブルを表示。
  - **★重要:** ステータスが「差戻し（否認）」の場合は、APIから渡された「差戻し理由（Reject_Reason）」を赤字で目立つように表示するコンポーネントを追加。

### 【Sprint 3】業務のループ完成：差戻し対応（再提出）
Sprint 1で作ったアップロード機能を再利用して、再提出を可能にします。

- [ ] **Step 8: 再提出アップロードUIの組み込み (FE)**
  - 詳細画面（ステータスが差戻しの場合のみ）に、Sprint 1で作った「CSVアップロードエリア」をコンポーネントとして呼び出して表示。
- [ ] **Step 9: `parent_id` を付与した送信処理 (FE/BE)**
  - 再提出時の「確定」ボタン発火時、Sprint 1の送信関数を再利用。
  - ただし、送信時のJSONペイロードに `parent_id: "元データのID"` を追加して送るように制御。
  - **[BE側]** GASで受け取り、モックシートに「新レコード追加 ＆ 親ID記録」が正しく行われるか確認。

### 【Sprint 4（最終調整）】共通基盤・本番結合
- [ ] **Step 10: 認証とセッション管理**
  - GASの標準機能でGoogleアカウント連携（メールアドレスの取得）を行い、卸ごとの「テナントID」として機能させる。
- [ ] **Step 11: BackOfficeとの本番API結合**
  - GAS側のモック（仮シート保存・取得）を剥がし、BackOffice側の本番API（`UrlFetchApp.fetch`）へ向けるようにリファクタリング。
